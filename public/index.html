Roadmap

8ヶ月でゴールできる理由

勉強して知識を習得すれば、「いつかWebアプリを作れるようになる」という曖昧な目標では、続きません。 コードコネクトでは、8ヶ月を3つのステップに分け、各ステップに必ず「作れた」という成果を置いています。 成果があるから、続けられる。続けられるから、到達できる。

わたしたちが大切にしているのは「知識の量」ではなく「経験の質」です。 手を動かして、失敗して、それでも動いたときの「できた」という体験が、次へ進む力になります。 3ヶ月ごとに、形を持つ成果が確実に生まれるから、 子どもたち自身が「これなら続けられるかも」と感じることができるのです。

例えば、Scratchで身についた「もし〜なら」という条件分岐の考え方は、JavaScriptのif文にそのまま対応しています。

Philosophy

「続けられる」授業を目指して

教室全体の設計だけでなく、授業ひとつひとつにも「続けられる」工夫で、途中でやめたくならない学びの流れをつくっています。

Principle 01

分からない人を、一人にしない

プログラミングでは、「あれ、思った通りに動かない」という「つまづき」が必ず出てきます。
その「つまずき」を一緒に見つけ、言葉にしていくことで、「自分で気づける」力を育てます。 そのためには、答えを教えるのではなく、考えるヒントを引き出します。 答えを自分で見つけ、自分の言葉にできた時、次へ進む自信へとつながります。

Principle 02

時間ではなく、理解の深さで進む

授業では「分かったつもり」で次へ進むのではなく、一緒に立ち止まって、繰り返し考え、時間をかけてでも「分かった」を目指します。 だからこそ、「3ヶ月で絶対に終わる」とは言いません。
お子さんによっては、理解のペースに合わせて、授業の回数を増やして対応します。
「早く終わらせること」より「確かな力が身につくこと」を、わたしたちは大事にしています。

Principle 03

競争ではなく、一緒に学び合う

講師1人に対して、生徒1〜3人の少人数制です。 他の子の考え方や疑問に触れることで、 「自分だけじゃない」という安心と、「別の考え方もある」という気づきが生まれます。 競争ではなく、相互作用で理解が深まる環境です。 そういう疑問や発見が、実は一番の学びになり、それが「続けられる」理由にもなります。

Class

「止まったまま」を作らない授業の中身

  • Duration 1回 : 90〜120分
  • Class Size 講師1人、生徒1〜3人
  • Instructor 最初から最後まで、担当講師は変わりません。

Scene 01

「手を動かす」がもちろん大事

基本的な授業構成は、最初の25分で「今日やること」を説明した後、残りの時間は「実装してみる」時間です。
お子さんが実際にコードを書き、動かして、失敗を経験する。
その過程で「なぜこう書くのか」を、その場で体験を通じて理解していきます。

Scene 02

エラーが出たら、そこが学びのチャンス

動かない→エラーメッセージを読む→原因を予測する→修正してみる。
この「試行錯誤のループ」こそが、実務に近いプログラミングの力になります。
失敗を恐れずに、その過程で何が起きているかを観察する癖をつけていきます。

Scene 03

異なる考え方が学びになる

同じボタン機能を実装するとき、A君はこう書いた、B君はこう書いた。
どちらも動く。なぜ両方が動くのか。どちらが読みやすいのか。
「別の考え方、作り方があるんだ」という発見が、その子の引き出しを増やします。
講師1人に生徒1〜3人だからこそ、そういう相互作用が自然に起きる環境です。
